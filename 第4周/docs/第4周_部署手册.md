## 一、这套系统由什么组成

### 1.1 服务清单（8 个容器）

| 服务 | 容器名 | 端口 | 作用 | 健康检查 |
|---|---|---|---|---|
| mysql | mysql | 3307→3306 | Hive Metastore 元数据库 + Superset 元数据 + 业务库快照 | mysqladmin ping |
| mysql-init | mysql-init | — | 一次性建库（superset_meta / ydsh_mysql），跑完退出 | 退出码 0 |
| hive-metastore | hive-metastore | 9083 | Hive 元数据服务 | 9083 端口可连 |
| hive-server | hive-server | 10000 / 10002 | HiveServer2，数仓主数据源 | 10000 端口可连 |
| clickhouse | clickhouse | 8123 / 9000 | 服务层缓存（ADS 结果集副本），压测对比用 | clickhouse-client select 1 |
| superset | superset | 8088 | BI 仪表板 | HTTP /health |
| superset-init | superset-init | — | 一次性初始化数据源/数据集/6 图表/仪表板，跑完退出 | 退出码 0 |
| api | ydsh-api | 8000 | JSON 数据接口 + 托管 ECharts 大屏 | HTTP /api/health |
| app | ydsh-app | 8501 | Streamlit 对话式问答 | HTTP /_stcore/health |

访问地址（部署成功后可逐个打开验证）：

- Superset 仪表板：http://localhost:8088/superset/dashboard/ydgmv-overview/
- ECharts 数据大屏：http://localhost:8000/
- Streamlit 问答：http://localhost:8501/
- 接口文档（自动生成）：http://localhost:8000/api/docs

### 1.2 启动顺序（由 compose 的 depends_on + healthcheck 保证）

```
mysql(healthy) ─→ mysql-init(完成) ─→ superset(healthy) ─→ superset-init(完成)
   │
   └─→ hive-metastore(healthy) ─→ hive-server(healthy) ─┬─→ api ─→ app
                                                        └─→ clickhouse(healthy)
```

顺序不是"写着好看"：Hive 冷启动要 60~120 秒，如果 Superset 抢跑，它会在元数据库还没建表时就去连 Hive，直接进入重启循环（第 3 周踩过一次 hive-server 崩溃循环，这次用 healthcheck 从机制上避免）。

## 二、首次部署（从零到能看仪表板，约 8~12 分钟）

### 2.1 前置检查

```powershell
docker version            # 需要 Docker Desktop 已启动，实测 29.9.2
docker compose version    # 需要 v2 语法
```

三项硬性要求：

1. 内存 ≥ 8 GB（Hive + Superset + CH 同时跑，实测占用约 5.2 GB）；
2. 端口 3307、9083、10000、10002、8123、9000、8088、8000、8501 未被占用；
3. 首次构建需联网拉 pip 包（已改用清华源）。

端口占用自查：

```powershell
netstat -ano | findstr "8088 8501 8000 8123"
```

### 2.2 准备环境变量

```powershell
Copy-Item .env.example .env
```

然后编辑 `.env`，最少要改三项：

| 变量 | 说明 | 不改的后果 |
|---|---|---|
| `SUPERSET_SECRET_KEY` | 会话签名密钥，必须随机 | Superset 拒绝启动（官方镜像的安全检查） |
| `LLM_API_KEY` | 大模型 Key；留空则 Streamlit 进演示模式 | NL2SQL 无法调用模型 |
| `CLICKHOUSE_PASSWORD` | ClickHouse 密码 | 用默认值也能跑，但不建议 |

生成随机密钥：

```powershell
docker run --rm python:3.12-slim python -c "import secrets;print(secrets.token_urlsafe(42))"
```

### 2.3 构建镜像

```powershell
docker compose build
```

会构建两个镜像：

- `ydsh/superset:4.1.2`：官方 Superset + PyHive/thrift/pure-sasl/PyMySQL 驱动 + 自定义配置（约 950 MB）
- `ydsh/app:4.0`：Python 3.12 + FastAPI/Streamlit/LangChain/PyHive（约 620 MB）

首次构建 3~6 分钟（取决于网速），之后改代码只重建上层，约 10 秒。

### 2.4 一键启动

```powershell
docker compose up -d
```

期望看到的关键日志（顺序很重要）：

```
Container mysql Healthy
Container mysql-init Exited (0)
Container hive-metastore Healthy
Container hive-server Healthy
Container superset Healthy
Container superset-init Exited (0)
Container ydsh-api Healthy
Container ydsh-app Healthy
```

`superset-init` 退出不算失败，它是"一次性任务型"服务，建完数据源/图表/仪表板就退出。

### 2.5 确认状态

```powershell
docker compose ps
```

8 个服务里除了 `mysql-init`、`superset-init` 显示 `Exited (0)`，其余都应为 `Up (healthy)`。

如果 Superset 一直在 `health: starting`：正常，首次启动要跑 30 多个数据库迁移，等 60~120 秒。

### 2.6 首次装载可视化所需数据（重要）

镜像构建只带代码，**不包含数据**。数仓数据在 `data/warehouse`（bind mount，长期保留），第 4 周新增的 2 张 ADS 表和两份外部副本需要执行一次：

```powershell
cd 第4周/py

# ① 建表 + 装载 + 校验（3 个脚本，约 2 分钟）
python sql_runner.py ../sql/ads/create_ads_w4.sql --out ../evidence/ads_w4_create.txt
python sql_runner.py ../sql/ads/load_ads_w4.sql   --out ../evidence/ads_w4_load.txt
python sql_runner.py ../sql/ads/verify_ads_w4.sql --out ../evidence/ads_w4_verify.txt

# ② 把 ADS 结果集复制到 ClickHouse（服务层缓存）
python export_to_clickhouse.py

# ③ 把 KPI 快照落到 MySQL（业务库角色，供 Superset 跨源演示）
python export_to_mysql.py
```

也可以直接双击 `第4周/一键运行/1_初始化可视化数据.bat`。

判断成功：`verify_ads_w4.txt` 末尾是 `失败 0 条`，且支付表 GMV 合计 = `36,116,687.06`、热力表销售额合计 = `35,833,305.06`。

> 换机器重建时 `data/warehouse` 若已随仓库带过来，数据仍在，只需补做 ClickHouse 与 MySQL 两份副本（②③）。

## 三、现场演示流程（答辩用，约 3 分钟）

任务书明确要求"现场演示一键部署启动全过程"，按这个顺序走最稳：

1. **停干净**（演示"从零启动"）：

```powershell
docker compose down          # 注意：不要加 -v，加了会把 MySQL/CH 数据卷删掉
```

2. **一条命令拉起**：

```powershell
docker compose up -d
docker compose ps            # 边等边解释 8 个服务的依赖关系
```

3. **看数据服务自检**：浏览器打开 http://localhost:8000/api/health ，展示 `hive` 版本号、`clickhouse` 版本号、当前后端 `backend`。

4. **看 ECharts 大屏**：http://localhost:8000/ （F11 全屏），说明 1920×1080 设计稿 + scale 自适应。

5. **看 Superset 仪表板**：http://localhost:8088 ，admin / admin，点开"云购生活 · 经营分析仪表板"，演示筛选器联动。

6. **看 Streamlit 问答**：http://localhost:8501 ，输入"各支付方式的销售额占比是多少？"，展示 SQL → 表格 → 图表。

7. **收尾**：说明密钥全部走 `.env`，`git status` 里看不到 `.env`。

## 四、常见问题（全部为本项目真实踩过）

### 4.1 Superset 报 `Refusing to start due to insecure SECRET_KEY`

原因：没设置 `SUPERSET_SECRET_KEY`。官方镜像检测到默认密钥会直接拒绝启动。
处理：`.env` 里填一个随机串，`docker compose up -d superset`。

### 4.2 Superset 保存 Hive 数据源报 422，日志里是 `cannot recognize input near 'SHOW' 'CATALOGS'`

原因：Superset 的 Hive 引擎规格继承了 Presto 的实现，建数据源时会执行 `SHOW CATALOGS` 来同步多目录权限；Hive 4.0.0 的 HiveServer2 不支持这条语法。
处理：已在 `第4周/docker/superset/superset_config.py` 里用 `FLASK_APP_MUTATOR` 关闭 Hive 的目录探测（`supports_catalog = False`）。日志出现下面这行即生效：

```
[superset_config] Hive 目录探测已关闭（app context 内生效）
```

### 4.3 `superset fab create-admin` 卡在 `Username [admin]:`

原因：在 compose 的 `/bin/sh -c "..."` 里传多行参数会被拆散，命令退化成交互模式，容器永远起不来。
处理：改用 `第4周/docker/superset/create_admin.py`（在 app context 里调 FAB 接口，幂等，已存在就跳过）。

### 4.4 ClickHouse 插入数据报 `filesystem error: in rename: Permission denied`

原因：`/var/lib/clickhouse` 用 `./data/clickhouse` 绑定挂载时，CH 在 Windows 文件系统上无法 rename 分区目录，数据一点写不进去。
处理：改用命名卷 `ydsh_clickhouse_data`（compose 里已改）。这是 Docker Desktop on Windows 的已知限制，不是配置错误。

### 4.5 仪表板 6 个位置都显示"没有找到相关图表的组件，是否已经删除"

原因：用 REST API 建仪表板时 `slices` 字段不被接受（返回 `Unknown field.`），图表和仪表板的关联表 `dashboard_slices` 是空的，前端拿到的 `charts` 是空数组。
处理：`bootstrap.py` 里用模型层写入关联（`link_dashboard_charts`），日志出现 `已关联 6 个图表到仪表板 1` 即正常。

### 4.6 图表建好了但取数报 `Chart has no query context saved`

原因：Superset 4.x 的图表有 `query_context` 快照字段，只有在前端点"保存"时才生成；纯 API 建图表不会自动写。
处理：`bootstrap.py` 建图表时一并写入 `query_context`。

### 4.7 端口被占用：`bind: Only one usage of each socket address`

原因：本机已有一个进程占用 8000/8501（例如手工 `python api_server.py`）。
处理：先停掉它（`Get-Process python | Stop-Process`），或改 compose 里的宿主机端口映射。

### 4.8 Hive 查询很慢（第一条 20 秒以上）

不是故障：Hive on Tez 每次提交查询都要起会话/编译执行计划。
项目里做了三层缓解：ADS 预聚合（把计算前移）、ClickHouse 服务层缓存（毫秒级）、接口层 10 秒 TTL 缓存。详见《第4周_压力测试记录》。

### 4.9 `docker compose down -v` 之后数据没了

`-v` 会删除命名卷 `ydsh_clickhouse_data`。`data/mysql`、`data/warehouse` 是 bind mount，不受 `-v` 影响，但 CH 副本需要重跑 `export_to_clickhouse.py` 恢复。

### 4.10 中文在 PowerShell 里显示成乱码

只是控制台编码问题，不影响数据。看日志前执行：

```powershell
[Console]::OutputEncoding=[Text.Encoding]::UTF8
```

|---|---|
