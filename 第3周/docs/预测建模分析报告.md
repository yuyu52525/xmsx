## 一、结论先行

1. **线性回归在测试集上 MAPE 12.72%、MAE 13,489.58 元**，比"昨天=今天"的朴素基线（MAPE 20.08%）**误差降低 36.7%**，说明模型确实学到了日间规律。
2. **但模型没有跑赢"直接预测历史均值"这个常数基线**：单次留出上常数基线 MAPE 12.11%，比线性回归还低 0.61 个百分点；6 折滚动回测里两者 MAE 相差不到 0.7%。
3. 因此本报告的核心判断是：**这份数据只支持"短期水位预测"，不支持"经营决策级预测"**。7 天预测值（日均 97,979.43 元）应当理解为"未来一周 GMV 大概率落在 9.8 万上下"，而不是"下周能做到 68.6 万"。
4. 模型存在**系统性低估**（MBE +5,655.56 元），12 月的上行被明显低估，最差一天少估 41,769.29 元。只报 MAPE 会掩盖这个问题，所以本报告同时报 MBE。

> 一句话：**模型是可用的，但它的价值在于"量化不确定性"，不在于"给准数"。**

**关键观察**：CV 只有 0.187，日 GMV 高度围绕均值波动，没有明显趋势项。这一点直接决定了后面"常数基线很难被打败"——**当序列本身接近平稳时，任何复杂模型都很难证明自己比"均值"更有信息量**。

- 7 日移动平均在 9.0 万 ~ 10.8 万之间小幅摆动；

- **没有可见的长期上升或下降趋势**，也没有明显的年度季节性。

## 三、特征工程

| 特征 | 含义 | 构造方式 |
|---|---|---|
| `lag_1` | 昨日 GMV | `gmv.shift(1)` |
| `lag_7` | 上周同日 GMV | `gmv.shift(7)` |
| `ma_7` | 前 7 日均值 | `gmv.shift(1).rolling(7).mean()` |
| `ma_14` | 前 14 日均值 | `gmv.shift(1).rolling(14).mean()` |
| `dow` | 星期几（周一=0） | `order_date.dt.dayofweek` |
| `is_weekend` | 是否周末 | `dow >= 5` |
| `month` | 月份 | `dt.month` |
| `day` | 日 | `dt.day` |

**防泄漏处理**：所有滚动特征都先 `shift(1)` 再 `rolling()`，只用"昨天及更早"的信息。如果写成 `rolling(7).mean()`（不 shift），当天 GMV 会进入自己的特征，测试集指标会虚高到不可信的程度。

**踩过的坑**：`ma7` / `ma30` 是给画图用的列，最初 `dropna()` 无差别判空，`ma30` 需要 30 天窗口，白扔了开头 29 天，训练集从 322 天缩到 307 天。改为 `dropna(subset=FEATURES)` 后恢复。

## 四、模型与验证方案

### 4.1 模型选择

| 模型 | 说明 |
|---|---|
| 线性回归（LR） | 基线模型，系数可解释 |
| 梯度提升树（GBR） | `n_estimators=300, lr=0.05, max_depth=3`，非线性的树模型 |
| 朴素基线 | 用昨日 GMV 当今日预测 |
| 常数基线 | 一律预测训练集日均值 |

**关于 XGBoost**：任务书举例提到 XGBoost / Prophet / ARIMA，但本机运行环境实测 **`xgboost`、`lightgbm`、`statsmodels`、`prophet` 均未安装**（只有 `scikit-learn 1.9.1` 与 `scipy 1.18.1`）。因此用 sklearn 的 `GradientBoostingRegressor` 替代——它和 XGBoost 同属梯度提升家族，核心差异只是 XGBoost 多了二阶导与正则项，**在本数据量级下不足以改变结论**。

ARIMA / Prophet 未使用的原因不是装不上，而是**没有意义**：ARIMA 需要差分与自相关结构，而本序列 30 日移动平均近乎水平线、自相关以短期为主，ARIMA 最终会退化成"常数 + 噪声"——这恰好就是本报告里的常数基线，我们已经把它作为对照模型放进来了。**与其硬套一个会退化成均值的模型，不如直接把"均值"作为显式基线。**

### 4.2 验证方案（两层）

**第一层：单次时序留出**

- 训练集：322 天（2024-01-15 ~ 2024-12-01）
- 测试集：30 天（2024-12-02 ~ 2024-12-31）
- **严格按时间切分，绝不打乱顺序**——打乱会造成"用未来预测过去"的信息泄漏。

**第二层：滚动起点回测（rolling-origin）**

- 6 折 × 30 天，测试块互不重叠，覆盖 2024-07-05 ~ 2024-12-31；
- 第 k 折用"该块之前的全部数据"训练，预测该块；
- 这一步是为了验证"单次留出的结论是不是运气"。**单次 30 天窗口只有 30 个样本，结论非常容易被偶然性左右。**

> 注意：回测是一步预测（特征里的 lag 用真实值），比第 7 节的递归多步预测乐观，**只能用于横向比较模型，不能当作上线精度**。

### 4.3 评价指标

| 指标 | 含义 | 为什么要看 |
|---|---|---|
| MAE | 平均绝对误差 | 直观、与 GMV 同量纲 |
| RMSE | 均方根误差 | 对大误差更敏感 |
| MAPE | 平均绝对百分比误差 | 跨量级可比 |
| **MBE** | 平均偏差（实际−预测） | **识别系统性高估/低估**，MAPE 看不出来 |

## 六、结果解读（这一节比指标本身更重要）

### 6.1 三个反直觉的发现

**发现一：复杂模型反而更差**

GBR 在单次留出上 MAPE 17.28%，比线性回归差 4.56 个百分点，甚至接近朴素基线。原因：GBR 用递归特征做多步外推时，树模型**无法外推到训练集见过的数值范围以外**，一旦滞后值偏离历史区间，输出就被"夹"在训练分布内。

**发现二：线性回归"赢"得不牢靠——MAE 与 MAPE 排名冲突**

看滚动回测：按 MAE，常数基线（13,853.92）优于线性回归（13,951.19）；按 MAPE，线性回归（14.33%）优于常数基线（14.96%）。

这不是矛盾，是两个指标关注点不同：MAPE 对 GMV 较低的日期更敏感（除以小分母），MAE 对所有日期一视同仁。**结论依赖指标选择，说明两者差距在统计上不可区分**——0.6 个百分点的差异，在 30 天样本上完全可能是噪声。

诚实的说法是：**线性回归与"预测均值"效果相当，机器学习没有带来实质增量。**

**发现三：线性回归的系数出现负值，说明它学的不是结构**

| 特征 | 系数 |
|---|---|
| `is_weekend` | +1,409.07 |
| `month` | -431.38 |
| `day` | +252.59 |
| `dow` | +210.45 |
| `ma_7` | **-0.37** |
| `lag_1` | **-0.17** |
| `ma_14` | +0.14 |
| `lag_7` | +0.03 |
| 截距 | 133,163.37 |

`ma_7` 和 `lag_1` 的系数是负的，而 `ma_14` 是正的——**这在业务上无法解释**（"昨天卖得多，今天应该卖得多"才符合直觉）。根因是这四个滞后特征高度共线（都在度量同一个"当前水位"），普通最小二乘在共线条件下系数不稳定，正负可以任意翻转，最后靠 13.3 万的截距把整体拉回合理区间。

**结论：这个模型的系数不可解释，不能用它做"哪个因素影响 GMV"的归因。** 它只是一个拟合水位的黑箱。若要做归因，应改用岭回归/主成分回归，或直接只用 `ma_7` 一个特征。

GBR 的特征重要度更符合直觉（`ma_14` 0.2358 > `lag_1` 0.2088 > `ma_7` 0.1929），但它预测精度反而更差——**"可解释"与"预测准"在这一点上是分离的**。

### 6.2 系统性低估

线性回归的 MBE = **+5,655.56 元**（正数表示实际高于预测）。测试集最后 5 个最大误差全部是低估：

| 日期 | 星期 | 实际 GMV | 预测 | 误差 |
|---|---|---|---|---|
| 2024-12-10 | 周一 | 136,084.44 | 94,315.15 | **+41,769.29** |
| 2024-12-15 | 周六 | 135,431.45 | 94,869.18 | +40,562.27 |
| 2024-12-20 | 周四 | 131,486.69 | 97,231.90 | +34,254.79 |
| 2024-12-03 | 周一 | 119,443.94 | 86,730.03 | +32,713.91 |
| 2024-12-04 | 周二 | 118,885.78 | 86,583.23 | +32,302.55 |

12 月日均 100,378.93 元，比训练期均值 98,263.33 元高 2.15%，模型没能跟上这个上移。**这正是"递归预测"的固有问题：每一步都用自己上一步的预测当前置输入，误差单向累积，最终结果向历史均值回归。**

## 八、适用边界（答辩重点）

这一节是本报告真正的结论。**模型能做什么、不能做什么，比 MAPE 精确到小数点后两位重要得多。**

### 8.1 数据边界

| 边界 | 影响 |
|---|---|
| **只有 366 天、单一年份** | 无法区分"季节性"与"偶发波动"，也无法做同比验证 |
| **无节假日 / 促销 / 大促标记** | 双 11、618 这类结构性峰值无法被建模，模型会把它当异常值平滑掉 |
| **无流量 / 广告投放 / 库存字段** | 无法回答"为什么涨跌"，只能回答"大概多少" |
| **模拟数据本身均匀分布** | 品类、渠道、省份几乎均分（各约 12.5% / 25%），本报告发现的"规律"多半是模拟器特性，**不可外推到真实业务** |

### 8.2 指标边界

- **MAPE 在低 GMV 日会失真**：某天 GMV 只有 5 万，绝对误差 1 万就是 20%，而同样 1 万误差在 13 万的日期只占 7.7%。用 MAPE 做跨时期比较时要小心。
- **MAPE 看不出方向性偏差**：本模型 MBE +5,655.56，说明系统性低估，但 MAPE 只显示"平均差 12.72%"。**只报 MAPE 是不完整的。**
- **单次 30 天留出的结论不稳定**：这正是本报告加做 6 折滚动回测的原因——单次留出说"常数基线最好"，回测说"线性回归 MAE 略差但 MAPE 略好"，两者都不足以宣称"模型更优"。

### 8.3 模型边界

| 边界 | 具体表现 |
|---|---|
| **树模型不能外推** | GBR 预测值被"夹"在训练集数值范围内，GMV 突破历史高点时必然低估 |
| **线性模型共线不稳** | `lag_1` / `ma_7` 系数为负，无法解释，不能用于归因 |
| **递归误差累积** | 7 步递推中每步都用上一步的预测值，误差单向放大；实测 12 月系统性低估 |
| **无法建模结构性突变** | 新渠道上线、竞品降价、政策变化，模型完全无感知 |

### 8.4 业务边界（什么时候不能用）

以下场景**明确不建议**直接使用本模型的输出：

1. **年度 / 季度目标制定**——只有一年数据，无法支撑跨年预测；
2. **大促备货**——没有促销标记，模型会把峰值当噪声平滑掉；
3. **单日精确排班**——单日不确定性（P5~P95 跨度 6.9 万 ~ 12.9 万）远大于预测值本身的差异；
4. **归因分析**（"为什么这个月跌了"）——模型不能回答因果问题，请看 `第3周/docs/AI智能洞察与反思.md` 的归因章节。

### 8.5 什么条件下可以上线

满足以下**全部**条件后，才建议把这类模型接入生产：

- [ ] 至少 2 年完整历史（能算同比、能区分季节性与偶发）；
- [ ] 补齐促销日历、节假日、投放费用、流量等外生变量；
- [ ] 引入分层预测（先预测订单量 × 客单价，而不是直接预测 GMV），让误差可分解；
- [ ] 用滚动回测而非单次留出做验收，并同时看 MAE / MAPE / MBE；
- [ ] 给出预测区间（如 P10~P90），而不是只给点估计；
- [ ] 建立"预测 vs 实际"的每日回写与漂移监控。

## 九、改进方向（按性价比排序）

| 优先级 | 改进 | 预期收益 |
|---|---|---|
| 高 | 加促销/节假日标记（即使是人工标注） | 消除结构性峰值的系统性低估 |
| 高 | 改预测目标为"订单量 × 客单价" | 误差可分解，客单价相对稳定，订单量更好建模 |
| 中 | 用岭回归替代 OLS | 解决共线性导致的系数翻转，系数变得可解释 |
| 中 | 输出预测区间（分位数回归 / 残差自助法） | 直接支撑"备货下限/上限"类决策 |
| 中 | 引入 Sarimax / Prophet（需先装依赖） | 若补齐 2 年数据，可显式建模周季节与趋势 |
| 低 | 调 GBR 超参 | 在 366 样本上收益有限，且无法解决外推问题 |

## 附：一句话总结

> 我们用一个线性模型把日 GMV 的预测误差从 20.08% 降到 12.72%，但随后发现"直接预测历史均值"能做到 12.11%——**这个发现比模型本身更有价值**：它说明在只有 366 天、没有外生变量的条件下，任何模型的边际贡献都很小。所以本报告交付的不是"一个能预测 GMV 的模型"，而是**"一个能说清自己什么时候不该被信任的模型"**。
